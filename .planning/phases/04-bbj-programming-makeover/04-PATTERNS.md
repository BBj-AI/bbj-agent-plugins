**Compiler call** (lines 655-675; argv list, never a shell, stdin `/dev/null`, exit status ignored because it is 0 on every outcome, stderr merged for the record; one file per call for clean per-probe output, per RESEARCH Pattern 5):
```python
done = subprocess.run([cpl] + CPL_ARGS + [path], cwd=workdir, stdin=subprocess.DEVNULL,
                      stdout=subprocess.PIPE, stderr=subprocess.STDOUT, timeout=CPL_TIMEOUT)
```

Compiler path rule (`bbjcpl_path`, lines 574-582): `BBJ_TEST_HOME` or `/opt/bbx`, `bin/bbjcpl`, regular executable file. Every call carries `-N` (static gate). Probes are compiled only, never run.

**bbj-ls call** (lines 730-735 `url_ok`, 758-782 `ls_call`, 785-811 `ls_verdict`): loopback-only URL check, no proxy and no redirects (`OPENER = urllib.request.build_opener(urllib.request.ProxyHandler({}), _NoRedirect())`, line 727), JSON-RPC `tools/call` of `bbj_check_syntax` with the headers `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`; reply reduced to the last `data:` line; verdict `pass` when text starts `No errors found.`, `fail` when a `line N, column M:` line exists (`LS_LINE_RE`), else no verdict. Version read from `structuredContent.bbjVersion`:
```python
body = {"jsonrpc": "2.0", "id": 1, "method": "tools/call",
        "params": {"name": "bbj_check_syntax", "arguments": {"code": code},
                   "_meta": {"io.modelcontextprotocol/protocolVersion": PROTOCOL,
                             "io.modelcontextprotocol/clientCapabilities": {}}}}
headers = {"Content-Type": "application/json", "MCP-Protocol-Version": PROTOCOL,
           "Mcp-Method": "tools/call", "Mcp-Name": "bbj_check_syntax"}
```
Read the code from the file as data; never interpolate it into a command.

**Output:** write `probes/OUTPUT.txt` with the BBj version, then per probe: file name, bbjcpl text, bbj-ls verdict + first error line. Use a canary pair like the gate (`CANARY_GOOD = 'print "a"; rem ok\n'`, `CANARY_BAD = 'print "a"   rem same line\n'`, lines 140-142) so a dead compiler cannot read as "all clean".

**Error handling:** every transport/parse failure becomes text, never an exception (`ls_call` returns `(None, error_text)`); exit 1 if a canary misbehaves.

**Script header/exit style:** copy the header shape from `.planning/phases/02-hook-no-route-notice/evidence/capture-claude.sh:1-26` (path line, plan/decision IDs, usage, exit codes "0 done, 1 a check failed, 2 refused before any change", "never runs BBj"). That script is `sh`; run.py should keep the same header content as a docstring.

## Shared Patterns

### Gate dry run before committing
**Source:** `tests/test_skill_examples.py` (ROOT argument, lines 98-125); RESEARCH Pattern 4.
**Apply to:** every SKILL.md and reference change.
Build a scratch root with `plugins/bbj/skills/bbj-programming/...` and `tests/skills_baseline.json` = `{"bbj_version":"26.03","nocheck":0,"pending":{}}`, then:
```
BBJ_SKILLS_LIVE=1 python3 -I tests/test_skill_examples.py <ROOT>
```
Put the scratch root under the scratchpad directory, not `/tmp`.

### Fence grammar
**Source:** `OPEN_RE`, `NOCHECK_RE`, `NON_BBJ` (lines 130-133). **Apply to:** all blocks.
Allowed tags: `bbj`, `bbj should-fail`, and non-BBj tags (`css html js json bash sh text xml`). No untagged fence, no `...`.

### should-fail acceptance
**Source:** `block_outcome` (line 700ff). A `should-fail` block must fail at least one live route (`bbjcpl` only is acceptable, D-07); a passing one is a violation.

### Layout rules
**Source:** `tests/test_layout.py:138-140,175-180`. Skill files: no hosted host name outside `plugin.json`, no executable files.

### Style for any script or test touched
**Source:** CLAUDE.md conventions. POSIX `sh` or stdlib Python only; Python run as `python3 -I`; `gate NAME ok|FAIL|skip` output; no `set -e` in shipped shell; header comment with plan/decision IDs and "never runs BBj".

### Commits
Conventional prefix with plan scope, e.g. `docs(04-01): ...`; do not commit unless asked.
