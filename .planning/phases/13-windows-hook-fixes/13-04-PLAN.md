**Windows and Git Bash facts the launcher must respect** (planner's reading of Git for Windows, Codex rust-v0.162.1 and RESEARCH):
- Git Bash mounts `/` at the Git root and `/bin` and `/usr/bin` at `<Git>\usr\bin`. So never build a Git directory for PATH with `cygpath -u`; build the cygdrive form from the Windows path instead (helper `drivepath`: `C:\X\Y` becomes `/c/X/Y`, lower-case drive letter, backslashes to slashes). `cygpath -w /` prints the Git root with a trailing backslash; `cygpath -m P` prints `C:/...`.
- When a Git Bash program starts a native one, MSYS converts PATH from the POSIX list to the Windows list, passes other variables that hold Windows paths unchanged, and converts arguments unless `MSYS_NO_PATHCONV=1` is in the environment of the program that does the start; with `env -i` the variable must be in the new environment too.
- Codex starts the hook with Rust's `Command` (MSVC argument quoting, stdin piped, written, closed; Codex's own environment). Git Bash quotes arguments for a native program the same way. The pinned string has no backslash directly before a double quote, so the quoting is unambiguous.
- A variable whose name holds parentheses is passed as an argument of `env`: `"ProgramFiles(x86)=$_dir"`.
- Junctions: create with `New-Item -ItemType Junction -Path P -Target T` through powershell (no admin needed); remove with `cmd //c rmdir "P"` (no /s; removes only the link). Windows PowerShell 5.1 `Remove-Item -Recurse` and recursive deletes can follow a junction into its target, so nothing recursive may run on a directory that still holds a junction.
- ConstrainedLanguage: prefix the command text with `$ExecutionContext.SessionState.LanguageMode = "ConstrainedLanguage"; ` (allowed from FullLanguage; the planner's pwsh 7.6.7 check used this prefix).
- The commandWindows value: extract the JSON string of the `"commandWindows": "..."` line of hooks.json with sed and unescape `\"` then `\\`; selftest compares the result with `python3 -I` `json.load` when python3 exists; `run` prints its sha256 (plan 13-02 pin: `ae8707fbeb83c04b531c0c61f84980447d53c9424749d60c73eeb53070697d51`). `${CLAUDE_PLUGIN_ROOT}` is replaced textually (awk index/substr) by `cygpath -m` of `<checkout>/plugins/bbj`; refuse a root that holds `$`, a backtick or a quote.
- Hook output (09 runs and the tests): a bad file gives exit 2 and the first stderr line `bbjcpl reported 1 error(s) in <file>:`; the not-found branch gives exit 2 and three stderr lines, the first `bbj-check: Git for Windows sh.exe not found, so BBj files are not compile-checked.`. Fixture lines from the 09 runbook: bad `print "a"   rem same line`, clean `print "a"; rem ok`.
- Codex payload: the key order of `codex_payload` in tests/lib.sh; Codex 0.162.1 sends the Windows cwd and an absolute `*** Add File: ` path (09 capture); JSON-escape backslashes and quotes.
