<objective>
FIX-02 (Phase 9 review WR-02): one hook run pays the tier-2 connect cost once, not once per file,
so a many-file Codex `apply_patch` with no check route ends well inside the 30 s hook timeout
(D-11 to D-15). The first "nothing reached" outcome of a hook run (refused, no curl, URL refused,
and new: a connect timeout where no TCP connection was made) is remembered in the existing global
`NR_T2`, and every later BBj file of the same run skips curl but is still counted and listed in
the no-route notice (D-14). A reached route (a verdict, a slow or broken reply) is never cached,
so an answering bbj-ls still checks every file (D-11). A bbj-ls that accepts the connection and never answers is such a reached route: it is outside "no check route", and its cost of up to `-m 12` per file is the limit the owner accepted in D-11 (no reached route is cached, a slow reply included) and D-13 (no total time cap).

The tracer wires the cache through the whole path first: Codex payload with 12 files, the
Windows branch, `check_file`, `no_tier1_route`, the notice, and a gate that goes red when the
cache line is deleted. The expansion adds the connect-timeout classification (D-12) and the
"reached is never cached" proofs.

Purpose: SC2 of Phase 13 (FIX-02), and half of SC4.
Output: the hook change, the fake-curl write-out seam, four gates in tests/test_tier2_fake.sh.
The permanent mutation case for the cache line lives in plan 13-03 (D-18).
</objective>
