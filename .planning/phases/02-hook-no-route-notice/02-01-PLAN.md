<objective>
Make plugins/bbj/scripts/bbj-check.sh tell the agent, once per session, that a BBj file it wrote was
not checked when no check route exists, instead of exiting silently. This plan builds the whole
notice (exact JSON object, both client texts, path list, once-per-session marker with every edge
case) on the "no compiler found" branch, where tier 2 decides between no route and a failed route.
Plan 02-02 adds the second entry into the notice (a compiler that gives no verdict, D-02), the exit
contract amendment and the "never notifies" matrix.

Decisions implemented here: D-01, D-03 (curl classification), D-04 (notice only when FAILED=0),
D-06, D-07, D-08, D-09, D-10, D-11, D-12, D-16, D-17, D-18, D-19. Requirements: HOOK-01 (no route vs
route failed on the tier-2 path), HOOK-02, HOOK-03 (conversion of 14 silent-path gates).

Purpose: an agent that writes BBj on a machine with no compiler and no bbj-ls learns that its file
went unchecked and can tell the user how to enable a check, instead of reading silence as "clean".

Output: the changed hook script, the new test file tests/test_noroute_notice.sh, the hermetic state
seam in tests/lib.sh, and the converted gates in tests/test_discovery.sh and tests/test_tier2_fake.sh.

      code to that server and checks it against a stock BBj, so the user must be told.
  S5  Tell the user that this file was not compile-checked and how to enable a check.

check stays outside the hook's route model (no-change there): it is text for the agent, the hook
never calls it, so the two hook tiers are unchanged. Invariant test, accepted: plan 02-02 Task 2
gates every outcome class and asserts that only "no route" prints the notice.
