<objective>
Finish `--remove` (CODEX-06; D-01 to D-04): refuse the option combinations that would contradict
the decisions before anything is written, and prove that every form the installer did not write is
left in place with exit 3, object by object, while the installer's own objects are still removed.

Purpose: plan 08-03 proved the round trip for every installer-written form. This plan proves the
other side of D-02, D-03 and D-04: a user's own edits are never deleted. That is the safety
property the switch to the plugin route rests on.

Decision applied (D-03 over RESEARCH A10): `--remove --force` is refused with exit 2. The research
suggested letting `--force` delete a differing skill directory. D-03 says a differing directory is
left and reported. The refusal message tells the user to copy out what they want and delete the
directory by hand. A 0.1.0 install, whose skills differ from 0.2.0, follows that documented step
(plan 08-07 writes it into the switch section).

Wave-1 closing gate: this plan depends on all three wave-1 plans (08-01, 08-02, 08-03), although
only 08-03's files are its input. The wave-1 plans run in parallel, so each of them verifies only
its own test files and never `tests/run.sh` ("Wave-1 isolation" in each). Task 2's full-suite run
is therefore the first one on the merged wave 1. Nothing in plan 08-05, the other wave-2 plan,
lies under `tests/`, so that run does not depend on a sibling's edits either.

Output: two refusals in `codex/install-codex.sh`, the remove-mode exit lines in its header and
usage, and 15 `remove_` gates in `tests/test_install_codex.sh`.
</objective>
