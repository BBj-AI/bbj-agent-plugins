<objective>
Give `install-codex.sh` a `--remove` option that undoes exactly what the installer wrote, so a user
of the installer route can switch to the plugin route and end with one hook, one copy of the
skills and one `bbj-docs` server (CODEX-06; D-01 to D-05). This plan builds the option and proves
the round trip for every form the installer writes. Plan 08-04 adds the refusals and the
left-in-place matrix.

Purpose: a user who adds the plugin on top of an installer install gets two hook entries (double
check, double feedback), the skills in `~/.agents/skills` and in the plugin cache, and an
`[mcp_servers.bbj-docs]` table that overrides the plugin's server (spike 002 step 5). The removal
is the documented way back to one of each (D-06: the docs, not the hook, handle the double
install).

Decisions applied:
- D-01: `--remove` never calls `codex`. The user then runs the two `codex plugin` commands
  (printed as next steps).
- D-02 plus RESEARCH Pitfall 1: the OAuth sub-table the installer writes since quick 261013-cpn is
  removed with its table. Leaving it would orphan a sub-table that the next install would treat as
  foreign.
- D-03: skills only when identical; the check script and its directory always.
- D-04: hooks.json only when byte-identical; the backup and Codex's trust entries are left.
- RESEARCH A11 (planner choice within D-02, "in the forms the installer writes"): the bbj-docs
  table is removed only when its url equals the `--docs-url` in effect. A custom-url registration
  is also the documented Codex override of the plugin's URL (spike 002 step 5), so it is never
  removed silently. The user repeats the same `--docs-url` to remove it.
- D-03 over RESEARCH A10: the research suggested that `--remove --force` delete a differing skill
  directory. D-03 says a differing directory is left and reported, so `--force` is refused with
  `--remove` (plan 08-04), and the docs tell a 0.1.0 user to delete such a directory by hand
  (plan 08-07).

Output: the option and its functions in `codex/install-codex.sh`, and 14 `remove_` gates.
</objective>

Installer, `codex/install-codex.sh`:

1. Options. Add `--remove` to the option loop (sets `remove=1`; initialise `remove=0` with the other
defaults). `--docs-url`, `--skills-dir` and `--codex-home` keep their meaning and validation in
remove mode: the same paths and the same url the install used. The two combination refusals (with
`--with-local`, with `--force`) are plan 08-04's.

2. Pre-flight without mkdir. Wrap the install pre-flight (the `mkdir -p "$codex_home"`, the
canonicalisation, `mkdir -p` of the skills dir and the script dir, and the writability loop) in
`if [ "$remove" = 0 ]`. In remove mode, do this instead:
   - refuse (exit 2) when `$codex_home` is not an existing directory, with the message
     `$codex_home is not a directory; nothing to remove`;
   - canonicalise it with `cd ... && pwd` and keep the existing shell-character check;
   - set config, `script_dst` and `script_dir` exactly as the install path does;
   - refuse when the Codex home, an existing skills dir, an existing script dir or an existing
     config.toml is not writable.
   Remove mode creates no directory: the anti-pattern in RESEARCH, because new H and D snapshot
   lines would break the round trip.

3. Renderer. Move `json_str` and the computation of `hook_cmd` and `hook_cmd_win` (with the
`cygpath` branch) above the main flow, and add `render_hooks`, which prints the exact block step 4
printed (same printf format string). Step 4 now runs `render_hooks > "$tmp"`. Every existing gate
must keep passing, so the bytes do not change.

4. analyze gains two output lines:
   - `inblock=1|0`: the server's main header lies between a `srv_begin` line and the next
     `srv_end` line.
   - `extra=1|0`: 1 when a non-blank line inside the server's main, oauth or srv_tools tool tables
     is something other than one of these:
     - the `url` key line;
     - the exact `srv_old_key` line;
     - an `approval_mode` key line in a tool table;
     - one of the three exact OAuth lines `client_id = "..."`, `callback_url = "..."` and
       `callback_port = N` built from `srv_oauth_*`.
     A comment counts as extra, because the installer writes none inside its tables. It is also 1
     when, between `srv_begin` and `srv_end`, a non-blank line lies outside those tables.
   The install path ignores both keys.

5. `remove_server`: for the srv_* globals (after `refresh` and `state`), set `rm_state` and
`rm_why`.
   - `absent`: main=0, mention=0, anytool=0 and managed=0.
   - `remove`, either of two cases:
     - markers only: managed=1, main=0, mention=0, anytool=0 and extra=0;
     - a full removable server: main=1, foreign=0, tools_foreign=0 and extra=0; dstate is `none`
       or `ours` (bbj-local: only `none`); for bbj-docs, `an url` equals `$docs_url`; every
       srv_tools tool is `approve` or `missing` and `anytool` equals the number of `approve`
       tools; oauth is `missing` or `ours`; when managed=1, inblock=1; for bbj-local, managed=1
       is also required (D-03 removes only the managed block).
   - `left` in every other case. `rm_why` names the first rule that failed. A url mismatch reads:
     `its url is <url>, not the --docs-url in effect (<docs_url>); rerun with --docs-url <url> to remove it`.
     A hand-registered bbj-local reads: it is outside the managed block (registered by hand).
     Anything else reads: it is in a form this script did not write.

6. `remove_tables`: one awk pass over config.toml into a mktemp file in the Codex home, then
`cat "$tmp" > "$config"` (in place, like the install side, so a symlinked config.toml keeps its
link and mode), then remove the temp file. The pass deletes:
   - the block from a `srv_begin` line through its `srv_end` line, when managed;
   - outside the markers, every `[mcp_servers.SRV]`, `[mcp_servers.SRV.oauth]` and
     `[mcp_servers.SRV.tools.NAME]` table: its header and its body up to the next header or marker
     line, matched by the same regexes analyze uses.
   Blank lines are buffered. A removed header or begin marker drops exactly one buffered blank line
   (the one the installer wrote before it). Buffered blanks that sit inside a removed region are
   discarded. A kept line emits all buffered blanks first. At end of file the buffer is discarded
   when inside a removed region, and emitted otherwise. Compare lines with a trailing `\r` stripped,
   but emit kept lines unchanged, so a CRLF file stays CRLF. Before the first change of an existing
   config.toml, write `config.toml.bbj-backup` when it does not exist yet, with the same rule and
   message as the install side.

7. `remove_all`, called right before the existing `use_docs` / `sync_server` lines when `remove=1`

     - `left`: print `$srv: $config holds $srv in a form this script did not write; left in place: $rm_why`
