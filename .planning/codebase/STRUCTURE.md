## Directory Purposes

**`.claude/`:**
- Purpose: Project instructions read by agents working in this repository.
- Contains: `CLAUDE.md` only. Its conventions section holds the term list and the flat gate-prefix
  block that `tests/run.sh` checks.
- Key files: `.claude/CLAUDE.md`

**`.claude-plugin/`** (repository root):
- Purpose: Declares the marketplace `basis-bbj` and lists its plugins.
- Contains: One JSON file.
- Key files: `.claude-plugin/marketplace.json`

**`.github/`:**
- Purpose: CI for the repository.
- Contains: Workflow, Dependabot config, npm tooling for the `claude` CLI.
- Key files: `.github/workflows/ci.yml` (runs `sh tests/ci.sh` with `CI=true`),
  `.github/ci-tools/package-lock.json` (pinned, integrity-checked)
- Generated: `package-lock.json` is generated by npm but committed.

**`.planning/`:**
- Purpose: GSD workflow state. Not shipped in the plugin and not on `main`; it is committed on the
  planning branch `gsd/planning-setup`.
- Contains: `codebase/` (the map documents), `phases/`, `milestones/`, `PROJECT.md`, `ROADMAP.md`,
  `REQUIREMENTS.md`, `STATE.md`, and other planning records.
- Exempt from the layout gates: `tests/test_layout.py` does not scan it, so the facts in the map
  are checked by hand with `git ls-files`.

**`docs/`:**
- Purpose: The one human-facing install page, for Claude Code and Codex. Linked from `README.md`.
- Contains: Markdown only.
- Key files: `docs/install.md` (502 lines): eleven `## ` headings (Requirements, steps 1 to 4,
  Options, Check routes, Not covered, Windows, macOS, Update and remove).

**`plugins/bbj/`:**
- Purpose: The main plugin, installed by `claude plugin install bbj@basis-bbj` or
  `codex plugin add bbj@basis-bbj`.
- Contains: Manifest, Codex overlay, MCP declarations, hook config, check script, skills.
- Key files: `plugins/bbj/.claude-plugin/plugin.json` (user options `docs_url`, `bbj_home`),
  `plugins/bbj/.codex-plugin/plugin.json`, `plugins/bbj/.codex-mcp.json`, `plugins/bbj/.mcp.json`,
  `plugins/bbj/hooks/hooks.json`, `plugins/bbj/scripts/bbj-check.sh`

**`plugins/bbj/hooks/`:**
- Purpose: Declares the PostToolUse hook.
- Contains: `hooks.json` only. The matcher is `Write|Edit`; `command` is
  `sh "${CLAUDE_PLUGIN_ROOT}/scripts/bbj-check.sh"`; `commandWindows` is a PowerShell string that
  looks for the Git for Windows `sh.exe` and runs the same script.

**`plugins/bbj/scripts/`:**
- Purpose: Executable code shipped to users.
- Contains: `bbj-check.sh` (718 lines, POSIX sh). It is the only shipped program.

**`plugins/bbj/skills/`:**
- Purpose: Agent guidance for BBj programming and BBj web (DWC) development.
- Contains: Two skill directories, each with `SKILL.md` and `references/` (four files each).
- Key files: `plugins/bbj/skills/bbj-programming/SKILL.md`,
  `plugins/bbj/skills/bbj-web-programming/SKILL.md`
- Generated: No.

**`plugins/bbj-local/`:**
- Purpose: Registers the local `bbj-ls` MCP server; off by default.
- Contains: Manifest (`defaultEnabled: false`) and `.mcp.json` pointing at `http://127.0.0.1:5009/mcp`.
- Key files: `plugins/bbj-local/.mcp.json`

**`tests/`:**
- Purpose: Every automated check of the repository.
- Contains: Test scripts, runner and CI entry, fixtures.
- Key files: `tests/run.sh` (runner; also prints the `run_prefix_block` gate), `tests/ci.sh`
  (entry used by CI), `tests/lib.sh` (shared helpers), `tests/test_layout.py` (layout and term
  rules), `tests/test_hook_mutation.sh` (hook mutation harness), `tests/test_check_order.py`
  (check-order block of the skills), `tests/test_real_compiler.sh` (skipped without BBj)
- Fixtures: `tests/fake-bin/bbj`, `tests/fake-bin/bbjcpl`, `tests/fake-bin/curl`,
  `tests/fake-bin/cygpath`, `tests/fake_mcp.py` (fake MCP server) and `tests/skills_baseline.json`.
- Every test file, by area (`TESTING.md` says what each one locks):
  - the hook: `tests/test_exit_contract.sh`, `tests/test_discovery.sh`, `tests/test_codex_patch.sh`,
    `tests/test_tier2_fake.sh`, `tests/test_tier2_live.sh`, `tests/test_noroute_notice.sh`,
    `tests/test_never_execute.sh`, `tests/test_static_guards.sh`, `tests/test_real_compiler.sh`,
    `tests/test_hook_review_fixes.sh`
  - proof that gates can fail: `tests/test_hook_mutation.sh`, `tests/test_path_scrub.sh`,
    `tests/test_release_text_mutation.sh`
  - manifests, text and skills: `tests/test_layout.py`, `tests/test_release_text.py`,
    `tests/test_install_pages.sh`, `tests/test_skill_examples.py`, `tests/test_check_order.py`
  - CI wiring: `tests/test_ci_gates.sh`, `tests/test_ci_guards.py`, `tests/test_claude_plugin.sh`

## Key File Locations

**Entry Points:**
- `.claude-plugin/marketplace.json`: Marketplace listing, read by `claude plugin marketplace add`.
- `plugins/bbj/.codex-plugin/plugin.json`: Codex overlay manifest, read by `codex plugin add`.
- `plugins/bbj/scripts/bbj-check.sh`: Hook program, runs on every `Write`, `Edit` or `apply_patch`.
- `tests/ci.sh`: Full local and CI check.

**Configuration:**
- `plugins/bbj/.claude-plugin/plugin.json`: `docs_url` and `bbj_home` options.
- `plugins/bbj/.mcp.json`: the docs server `bbj` (`${user_config.docs_url}`).
- `plugins/bbj/.codex-mcp.json`: the docs server `bbj` for Codex, literal URL.
- `plugins/bbj-local/.mcp.json`: `bbj-ls` server on loopback.
- `plugins/bbj/hooks/hooks.json`: Hook matcher, `command`, `commandWindows` and timeout (30 s).
- `.shellcheckrc`: Shellcheck settings for `tests/ci.sh`.
- `.gitattributes`: `text=auto eol=lf`. Keep shell scripts LF.
- `.github/dependabot.yml`: Dependency update rules for pinned actions.

**Core Logic:**
- `plugins/bbj/scripts/bbj-check.sh`: Compile check (tier 1 and tier 2), Codex patch branch,
  no-route notice.

**Documentation:**
- `README.md`: Overview, install, the check hook, the skills, development.
- `docs/install.md`: The install page for both clients.
- `CHANGELOG.md`: Release notes.
- `.claude/CLAUDE.md`: Conventions, term list and gate-prefix block for agents.

**Testing:**
- `tests/run.sh`: Runs every `tests/test_*.sh` and `tests/test_*.py`, then checks the gate names
  against the prefix block.
- `tests/ci.sh`: Adds strict `claude plugin validate` and `shellcheck -s sh`.

## Naming Conventions

**Files:**
- Shell scripts: lowercase kebab-case with `.sh`: `bbj-check.sh`
- Tests: `test_<topic>.sh` or `test_<topic>.py` with snake_case topics:
  `test_never_execute.sh`, `test_hook_mutation.sh`
- Test helpers: `lib.sh`, `fake_mcp.py` (snake_case), `run.sh`, `ci.sh`
- Markdown content: lowercase kebab-case for references (`callback-performance.md`,
  `running-dwc-apps.md`); `SKILL.md` in uppercase for each skill
- Planning and map documents: UPPERCASE `.md` under `.planning/codebase/`
- Manifests: fixed names `plugin.json`, `marketplace.json`, `.mcp.json`, `.codex-mcp.json`,
  `hooks.json`

**Directories:**
- Plugin directories: lowercase kebab-case matching the plugin name: `bbj`, `bbj-local`
- Skill directories: match the skill name in `SKILL.md` frontmatter: `bbj-programming`,
  `bbj-web-programming`
- Standard plugin layout: `.claude-plugin/`, `hooks/`, `scripts/`, `skills/` (lowercase, no
  prefix); `.codex-plugin/` for the Codex overlay

**Identifiers in code:**
- Shell functions: lowercase snake_case: `check_file`, `no_tier1_route`, `find_cpl_on_path`,
  `codex_patch`, `notice`, `report`.
- Shell variables: short lowercase, prefixed `_` for scratch values: `_url`, `_reply`, `_n`;
  per-run no-route state in uppercase: `NR_N`, `NR_LIST`, `NR_COMPILER`, `NR_T2`, `NR_HOSTPORT`
- Environment variables: `BBJ_` prefix, plus `CLAUDE_PLUGIN_OPTION_*` set by the host

## Where to Add New Code

**New hook behaviour or check route:**
- Primary code: `plugins/bbj/scripts/bbj-check.sh` (add a function next to `check_file`;
  route output through `report`)
- Tests: `tests/test_exit_contract.sh`, `tests/test_never_execute.sh`, and a new
  `tests/test_<topic>.sh` for the new route, using `tests/fake-bin/`

**Windows behaviour of the hook:**
- Code: the `commandWindows` string of `plugins/bbj/hooks/hooks.json` and the Windows branch of
  `bbj-check.sh` (`WIN=1` when `cygpath` is on `PATH`).
- Tests: `tests/test_layout.py` pins the string; `tests/test_discovery.sh` drives the path
  conversion through the fake `cygpath`; `tests/test_hook_mutation.sh` proves the gates can fail.

**New MCP server or plugin:**
- Plugin directory: `plugins/<name>/` with `.claude-plugin/plugin.json`, `.mcp.json`
- Register it in `.claude-plugin/marketplace.json` (`source: ./plugins/<name>`)
- Validation: `tests/ci.sh` checks `plugins/<name>` only when added to its `for p in ...` list

**New skill content:**
- Add or change skill files directly; `tests/test_layout.py` applies the host and exec-bit rules,
  `tests/test_skill_examples.py` checks the fenced examples.

**New test:**
- Shell: `tests/test_<topic>.sh`, print `gate NAME ok|FAIL|skip DETAIL` lines, exit non-zero
  on failure. `tests/run.sh` picks it up automatically.
- Python: `tests/test_<topic>.py`, run with `python3 -I`.
- Pick a gate prefix that no existing gate name starts with, and add the test's block line to
  `.claude/CLAUDE.md` and to `.planning/codebase/CONVENTIONS.md` (same lines, same order).
  `run_prefix_block` in `tests/run.sh` fails when the file is missing from the block, when a gate
  name is under none of its listed prefixes, or when the two copies differ.

**New documentation:**
- Install steps: `docs/install.md` (there is one page for both clients)
- Release notes: `CHANGELOG.md`
- A new term for user text: the term list in `.claude/CLAUDE.md`, checked by `layout_term_list`.

**Utilities:**
- Shared shell helpers in the tests: `tests/lib.sh`
- The hook has no shared helper file; its helpers are functions in `bbj-check.sh` and the awk
  programs are strings at the top of the script.

## Special Directories

**`plugins/bbj/skills/`:**
- Purpose: The two BBj skills, maintained in this repository.
- Generated: No.
- Committed: Yes.

**`.planning/codebase/`:**
- Purpose: Codebase map documents for GSD commands. `CONVENTIONS.md` holds a copy of the gate-prefix
  block that must match `.claude/CLAUDE.md`.
- Generated: Started by `/gsd-map-codebase`; STRUCTURE, TESTING, ARCHITECTURE and CONCERNS were
  refreshed by hand in Phase 14 so that the flat prefix block and the term list survive.
- Committed: On the planning branch only.

**`.github/ci-tools/node_modules/`:**
- Purpose: Installed `claude` CLI for CI.
- Generated: Yes, by `npm ci` in the workflow. Not committed (`.gitignore` does not list it,
  so it must stay out of the working tree; CI installs it fresh).

**`tests/fake-bin/`:**
- Purpose: Stub executables on `PATH` during tests (`bbj`, `bbjcpl`, `curl`, `cygpath`). They are
  never real BBj.
- Generated: No.
- Committed: Yes.
