## Directory Purposes

**`.claude-plugin/`** (repository root):
- Purpose: Declares the marketplace `basis-bbj` and lists its plugins.
- Contains: One JSON file.
- Key files: `.claude-plugin/marketplace.json`

**`.github/`:**
- Purpose: CI for the repository.
- Contains: Workflow, Dependabot config, npm tooling for the `claude` CLI.
- Key files: `.github/workflows/ci.yml` (runs `sh tests/ci.sh` with `CI=true`),
  `.github/ci-tools/package-lock.json` (pinned, integrity-checked)
- Generated: `package-lock.json` is generated by npm but committed.

**`.planning/`:**
- Purpose: GSD workflow state. Not shipped in the plugin.
- Contains: `codebase/` (maps, generated by `/gsd-map-codebase`), `seeds/` (dormant ideas).
- Key files: `.planning/seeds/SEED-001-skills-home-and-local-bbj-ls.md`
- Committed: Yes (seed is in git history).

**`codex/`:**
- Purpose: Everything needed to install the BBj plugin set for Codex, which has no marketplace
  here.
- Contains: Installer script and the instructions block a user pastes into `AGENTS.md`.
- Key files: `codex/install-codex.sh` (527 lines), `codex/AGENTS-snippet.md`

**`docs/`:**
- Purpose: Human-facing install guides, one per client. Linked from `README.md`.
- Contains: Markdown only.
- Key files: `docs/install-claude-code.md` (144 lines), `docs/install-codex.md` (149 lines)

**`plugins/bbj/`:**
- Purpose: The main plugin, installed by `claude plugin install bbj@basis-bbj`.
- Contains: Manifest, MCP declaration, hook config, check script, vendored skills.
- Key files: `plugins/bbj/.claude-plugin/plugin.json` (user options `docs_url`, `bbj_home`),
  `plugins/bbj/.mcp.json`, `plugins/bbj/hooks/hooks.json`, `plugins/bbj/scripts/bbj-check.sh`

**`plugins/bbj/hooks/`:**
- Purpose: Declares the PostToolUse hook.
- Contains: `hooks.json` only. The matcher is `Write|Edit`; the command is
  `sh "${CLAUDE_PLUGIN_ROOT}/scripts/bbj-check.sh"`.

**`plugins/bbj/scripts/`:**
- Purpose: Executable code shipped to users.
- Contains: `bbj-check.sh` (477 lines, POSIX sh). It is the only shipped program.

**`plugins/bbj/skills/`:**
- Purpose: Agent guidance for BBj programming and BBj web (DWC) development.
- Contains: Two skill directories, each with `SKILL.md` and `references/`.
- Key files: `plugins/bbj/skills/bbj-programming/SKILL.md`,
  `plugins/bbj/skills/bbj-web-programming/SKILL.md`
- Generated: No. Vendored from upstream BBjSkills at the commit in `skills.lock.json`.
  Do not edit.

**`plugins/bbj-local/`:**
- Purpose: Registers the local `bbj-ls` MCP server; off by default.
- Contains: Manifest (`defaultEnabled: false`) and `.mcp.json` pointing at `http://127.0.0.1:5009/mcp`.
- Key files: `plugins/bbj-local/.mcp.json`

**`tests/`:**
- Purpose: Every automated check of the repository.
- Contains: Test scripts, runner and CI entry, fixtures.
- Key files: `tests/run.sh` (runner), `tests/ci.sh` (entry used by CI),
  `tests/lib.sh` (shared helpers), `tests/test_skills_hash.py` (vendored-content lock),
  `tests/test_layout.py` (layout rules), `tests/test_install_codex.sh` (installer, 715 lines),
  `tests/test_real_compiler.sh` (skipped without BBj)
- Fixtures: `tests/fake-bin/` (stub `bbjcpl`, `bbj`, `codex`, `curl`, `cygpath`) and
  `tests/fake_mcp.py` (fake MCP server).

## Key File Locations

**Entry Points:**
- `.claude-plugin/marketplace.json`: Marketplace listing, read by `claude plugin marketplace add`.
- `plugins/bbj/scripts/bbj-check.sh`: Hook program, runs on every `Write` or `Edit`.
- `codex/install-codex.sh`: Codex installer, run from a checkout.
- `tests/ci.sh`: Full local and CI check.

**Configuration:**
- `plugins/bbj/.claude-plugin/plugin.json`: `docs_url` and `bbj_home` options.
- `plugins/bbj/.mcp.json`: `bbj-docs` server (`${user_config.docs_url}`).
- `plugins/bbj-local/.mcp.json`: `bbj-ls` server on loopback.
- `plugins/bbj/hooks/hooks.json`: Hook matcher and timeout (30 s).
- `skills.lock.json`: Upstream commit and per-file SHA-256.
- `.shellcheckrc`: Shellcheck settings for `tests/ci.sh`.
- `.gitattributes`: `text=auto eol=lf`. Keep shell scripts LF.
- `.github/dependabot.yml`: Dependency update rules for pinned actions and npm.

**Core Logic:**
- `plugins/bbj/scripts/bbj-check.sh`: Compile check (tier 1 and tier 2), Codex patch branch.
- `codex/install-codex.sh`: Codex install, config edit, skill and hook copy.

**Documentation:**
- `README.md`: Overview, install, the check hook, vendored skills, development.
- `docs/install-claude-code.md`, `docs/install-codex.md`: Install pages.
- `codex/AGENTS-snippet.md`: BBj instructions for `AGENTS.md`.
- `CHANGELOG.md`: Release notes.

**Testing:**
- `tests/run.sh`: Runs every `tests/test_*.sh` and `tests/test_*.py`.
- `tests/ci.sh`: Adds strict `claude plugin validate` and `shellcheck -s sh`.

## Naming Conventions

**Files:**
- Shell scripts: lowercase kebab-case with `.sh`: `bbj-check.sh`, `install-codex.sh`
- Tests: `test_<topic>.sh` or `test_<topic>.py` with snake_case topics:
  `test_never_execute.sh`, `test_skills_hash.py`, `test_install_codex.sh`
- Test helpers: `lib.sh`, `fake_mcp.py` (snake_case), `run.sh`, `ci.sh`
- Markdown content: lowercase kebab-case for references (`callback-performance.md`,
  `shadow-dom-styling.md`); `SKILL.md` in uppercase for each skill
- Planning and map documents: UPPERCASE `.md` under `.planning/codebase/`
- Seeds: `SEED-NNN-<slug>.md` under `.planning/seeds/`
- Manifests: fixed names `plugin.json`, `marketplace.json`, `.mcp.json`, `hooks.json`

**Directories:**
- Plugin directories: lowercase kebab-case matching the plugin name: `bbj`, `bbj-local`
- Skill directories: match the skill name in `SKILL.md` frontmatter: `bbj-programming`,
  `bbj-web-programming`
- Standard plugin layout: `.claude-plugin/`, `hooks/`, `scripts/`, `skills/` (lowercase, no
  prefix)

**Identifiers in code:**
- Shell functions: lowercase snake_case: `check_file`, `no_tier1_route`, `find_cpl_on_path`,
  `codex_patch`. Installer helpers are short: `say`, `refuse`, `analyze`, `state`.
- Shell variables: short lowercase, prefixed `_` for scratch values: `_url`, `_reply`, `_n`
- Environment variables: `BBJ_` prefix, plus `CLAUDE_PLUGIN_OPTION_*` set by the host

## Where to Add New Code

**New hook behaviour or check route:**
- Primary code: `plugins/bbj/scripts/bbj-check.sh` (add a function next to `check_file`;
  route output through `report`)
- Tests: `tests/test_exit_contract.sh`, `tests/test_never_execute.sh`, and a new
  `tests/test_<topic>.sh` for the new route, using `tests/fake-bin/`

**New Codex installer step:**
- Implementation: `codex/install-codex.sh`
- Tests: `tests/test_install_codex.sh` (uses a fake `codex` in a temp `HOME`)
- Docs: `docs/install-codex.md`; the AGENTS text goes in `codex/AGENTS-snippet.md`, whose
  tool list is checked against the installer by the test suite

**New MCP server or plugin:**
- Plugin directory: `plugins/<name>/` with `.claude-plugin/plugin.json`, `.mcp.json`
- Register it in `.claude-plugin/marketplace.json` (`source: ./plugins/<name>`)
- Validation: `tests/ci.sh` checks `plugins/<name>` only when added to its `for p in ...` list

**New skill content:**
- Do not add to `plugins/bbj/skills/` while the lock applies. Use the upstream
  BBjSkills repository; after re-sync, update `skills.lock.json`. Planned in-repo makeover:
  see `.planning/seeds/SEED-001-skills-home-and-local-bbj-ls.md`.

**New test:**
- Shell: `tests/test_<topic>.sh`, print `gate NAME ok|FAIL|skip DETAIL` lines, exit non-zero
  on failure. `tests/run.sh` picks it up automatically.
- Python: `tests/test_<topic>.py`, run with `python3 -I`.

**New documentation:**
- Install pages: `docs/install-<client>.md`
- Release notes: `CHANGELOG.md`

**Utilities:**
- Shared shell helpers in the tests: `tests/lib.sh`
- The hook has no shared helper file; its helpers are functions in `bbj-check.sh` and the awk
  programs are strings at the top of the script.

## Special Directories

**`plugins/bbj/skills/`:**
- Purpose: Vendored upstream BBj skills.
- Generated: No (copied from upstream).
- Committed: Yes. Byte-for-byte against `skills.lock.json`; `tests/test_skills_hash.py` fails
  on any change.

**`.planning/codebase/`:**
- Purpose: Codebase map documents for GSD commands.
- Generated: Yes, by `/gsd-map-codebase`.
- Committed: Yes (it is in the working tree; the orchestrator handles git).

**`.planning/seeds/`:**
- Purpose: Dormant ideas with trigger conditions.
- Generated: No (written by hand).
- Committed: Yes.

**`.github/ci-tools/node_modules/`:**
- Purpose: Installed `claude` CLI for CI.
- Generated: Yes, by `npm ci` in the workflow. Not committed (`.gitignore` does not list it,
  so it must stay out of the working tree; CI installs it fresh).

**`tests/fake-bin/`:**
- Purpose: Stub executables on `PATH` during tests. They are never real BBj.
- Generated: No.
- Committed: Yes.
