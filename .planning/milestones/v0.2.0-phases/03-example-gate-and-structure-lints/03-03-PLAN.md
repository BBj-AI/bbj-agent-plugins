<objective>
Add live route 1 of GATE-03: every checked block compiled by the real BBj compiler in one batched
`bbjcpl -t -N -X` call, with records mapped back to blocks, a canary pair that turns a dead compiler into
a visible broken route, the bbj / should-fail outcome rules, and the skip-unless-strict route gate. The
results flow through the same per-violation gates, ratchet, pending rule and report as the lint.

Decisions implemented here: D-08 (should-fail passes when at least one available route fails it),
D-10 (each block standalone, no wrapper), D-11 (route 1, batched, -N always), D-13 (skip without the
route, BBJ_SKILLS_LIVE=1 makes it a FAIL, CI=true stays a skip), D-14 (gate names with skill, file,
line and route; totals per route), D-20 (counts regenerated on this machine). Requirements: GATE-03
(route 1), GATE-01 (the should-fail rule).

Purpose: on a machine with BBj, every bbj example in the skills is compiled with type checking; the
failures of the two pending skills become counted to-do items and any new failure fails the suite.

Output: the extended tests/test_skill_examples.py and a regenerated tests/skills_baseline.json carrying
bbjcpl and should-fail counts measured here.

Research Open Question 4 decided: with only bbj-ls available a should-fail block that bbj-ls passes is
"undecided" (skip, FAIL under BBJ_SKILLS_LIVE=1), because bbj-ls cannot see type errors; with bbjcpl
available it is a violation. Research confirmed multi-file batching on BBj 26.03 (93 files, one call),
so the one-call-per-block fallback of D-11 is not needed and not built.
</objective>
