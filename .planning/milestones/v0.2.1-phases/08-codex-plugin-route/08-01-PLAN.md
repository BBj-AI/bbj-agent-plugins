<objective>
Give the `bbj` plugin a Codex overlay that registers `bbj-docs` at the literal docs URL, gate it so
the URL, the version and the hosted-host rule cannot drift, and prove in CI on fakes that the
plugin's unchanged `hooks/hooks.json` checks an `apply_patch` the way Codex runs it from its plugin
cache (CODEX-01, CODEX-02, CODEX-04; decisions D-10, D-11, D-13, D-14).

Purpose: Codex does not substitute Claude's `${user_config.docs_url}` (spike 001 saw
"relative URL without a base"). Spike 002 validated variant A: a `.codex-plugin/plugin.json`
overlay with `"mcpServers": "./.codex-mcp.json"`, which Claude Code ignores. This plan ships that
layout. Claude Code's manifest, `.mcp.json`, `userConfig` and `hooks.json` stay byte for byte as
they are. The marketplace stays the single `.claude-plugin/marketplace.json`, which Codex reads as
its legacy-compatible path (D-12); this plan creates no `.agents/plugins/marketplace.json`.

Decision recorded here (orchestrator, RESEARCH Open Question 1): `.codex-mcp.json` ships WITHOUT
an `oauth` object in this plan. Whether the plugin route can sign in to the hosted server without
one is settled by the Linux sign-in tries in plan 08-05. The owner chooses in that checkpoint, and
plan 08-08 asks the owner in a decision checkpoint and applies the answer. The layout gate pins
the exact dict now, and 08-08 re-pins it if the block is added.

Output: two new JSON files, five gate edits plus eight self-mutation gates in `tests/test_layout.py`,
six `plugin_route_` gates in `tests/test_codex_patch.sh`, and `CLAUDE_PLUGIN_ROOT` in the
hermetic unset of `tests/lib.sh`.
