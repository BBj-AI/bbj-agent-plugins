<objective>
Prepare everything the owner and the later plans need around the real runs (D-01, D-02, D-04 to
D-08, D-11, D-13 to D-16). This plan writes:
- the two runbooks the owner follows on Windows and macOS;
- the two record skeletons in the `08-LINUX-RUN.md` shape;
- a small checker that turns the record rules into commands every later plan can verify with:
  headings, verdict grammar, no empty `met`, no leaked home path, dated readings in order.

The runbooks hold the client steps that only a person can do: install, `/hooks` trust, real-model
writes, `bbj-local` enable and sign-in. They hold them as exact commands and prompts with a fixed
reply format, the shape of the 08-05 owner pass. The smoke script of plan 09-02 covers the rest. The
runbooks call it by its subcommands (`claude`, `codex`, `tier2`, `noroute`, `emit DIR`); that
interface is fixed in 09-02-PLAN.md, so this plan runs in parallel with it.

Nothing here is CI and nothing here edits the docs, README, CHANGELOG or the installer: the records
are what Phase 10 writes its wording from.
</objective>

1. `platform-run/check-records.sh` (`#!/bin/sh`, mode 100755, POSIX sh plus awk, no `local`, no
`set -e`). Usage: `sh check-records.sh windows|macos skeleton|filled|final [FILE]` and
`sh check-records.sh selftest`. FILE defaults to `../09-WINDOWS-RUN.md` or `../09-MACOS-RUN.md`,
relative to the script's directory. It prints one `check <name> ok|FAIL <detail>` line per check
and exits 0 when every check is ok, 1 when any failed, 2 on a usage error. The record contract it
encodes:
   - Windows headings, each exactly once, in this order:
     `## Run environment`, `## Install source`, `## Smoke run`, `## Claude Code: bbjcpl route`,
     `## Codex plugin route: bbjcpl`, `## Codex on Windows: spike 005 unknowns`,
     `## bbj-local: Claude Code`, `## bbj-local: Codex`, `## Tier 2 smoke`,
     `## No-route notice smoke`, `## Installer route (optional)`, `## Side readings`,
     `## Defects and re-runs`, `## Owner replies`, `## Verdicts`.
   - macOS headings: `## Run environment`, `## Install source`, `## Smoke run`,
     `## Claude Code: bbjcpl route`, `## Codex plugin route: bbjcpl`,
     `## Tier 2 smoke (optional)`, `## No-route notice smoke (optional)`, `## Side readings`,
     `## Defects and re-runs`, `## Owner replies`, `## Verdicts`.
   - Route sections, and the requirement IDs their verdict lines must name:
     - Windows: `Claude Code: bbjcpl route` names PLAT-01 and PLAT-02;
       `Codex plugin route: bbjcpl` names PLAT-03; `bbj-local: Claude Code`, `bbj-local: Codex`,
       `Tier 2 smoke` and `No-route notice smoke` each name PLAT-04 (the bbj-local and tier-2
       decisions D-13 to D-16); `Defects and re-runs` names PLAT-06.
     - macOS: both client sections name PLAT-05; `Defects and re-runs` names PLAT-06. The two
       optional sections must end with a line starting `Optional reading: ` instead (D-16).
   - Verdict line: a line starting `PLAT-0N: `.
     - Final values: `met`, `not run (REASON)`, `known gap (REASON)`, or
       `defect, fixed in <7 to 40 hex>, re-run met`.
     - Interim values, accepted in filled mode only: `defect, decision pending` and
       `defect, fix pending re-run`.
   - Dated reading line: `Reading YYYY-MM-DD, round N`.
   - Summary line in `## Verdicts`: `- PLAT-0N: <final value>`, one per requirement. Windows needs
     PLAT-01, 02, 03, 04, 06; macOS needs PLAT-05 and 06.
   - skeleton mode checks:
     - `headings`: every heading exactly once;
     - `placeholders_named`: the intro names `<home>` and `<checkout>`.
   - filled mode adds:
     - `no_skeleton_status`: no line holds the text `awaiting the owner's run` (the skeleton's
       section status lines and table values, written below);
     - `verdict_lines`: each route section holds verdict lines for exactly its IDs, each matching
       the final-or-interim grammar;
     - `readings_dated`: each route section holds at least one dated reading line;
     - `empty_section_met`: a route section whose verdict lines are all `met` holds at least one
       line indented by eight spaces (PLAT-06 edge);
     - `no_home_leak`: no line matches a Users path segment followed by anything other than `<`
       (in backslash, slash or `/c/` form), and no `/home/` path segment followed by anything
       other than `<`;
     - `environment_filled`: every row of the Run environment table has a non-empty value cell;
     - macOS only, `optional_reading_lines`.
   - final mode adds:
     - `no_interim`;
     - `verdicts_summary`: each required summary line present with a final value. A summary `met`
       is FAIL when any section line for that ID is neither `met` nor fixed-and-re-run-met;
     - `fixed_commits_exist`: `git cat-file -e <sha>^{commit}` for each `fixed in` value;
     - `readings_in_order`: per section, round numbers rise and dates do not fall; a section with
       a `fixed in` verdict holds at least two dated readings. This is the PLAT-06 ordering and
       re-run edge.
   - `selftest` builds, in a temp directory removed on exit and with printf only:
     - a minimal good Windows record and a good macOS record. Each `fixed in` uses
       `git rev-parse --short HEAD` of the checkout;
     - six mutants: a heading removed (skeleton FAIL), a `met` section with no indented line
       (filled FAIL), a line holding a Users path with a real-looking name (filled FAIL), a
       `defect, decision pending` line (filled ok, final FAIL), round 2 dated before round 1
       (final FAIL), a fixed verdict with one reading (final FAIL).
     It runs the checker on each, prints `selftest ok` when every expectation held, else
     `selftest FAIL <case>`, and exits 0 or 1.
   - Header comment: the path, the purpose, plan 09-03, D-05, D-08 and D-09, not CI, never runs
     BBj, reads only the record files and git.
