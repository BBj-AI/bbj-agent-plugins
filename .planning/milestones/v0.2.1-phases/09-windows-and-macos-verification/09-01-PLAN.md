<objective>
Pin the hook's Windows branch on fakes before anyone runs it on a real Windows machine (PLAT-02,
D-04, D-12; RESEARCH Pattern 1 and "The gates to add to tests/test_discovery.sh"). Today every
Windows gate starts from a Unix path, because the fake `cygpath -u` echoes its argument. This plan
adds a backward-compatible seam, `FAKE_CYGDRIVE_ROOT`, so `-u` can turn `C:\...` into a real path
under the test directory. Then it adds the gates for the four PLAT-02 facts (compiler from a
drive-letter home, drive-letter file path, `-P` list joined with `;`, a project path with a space)
and the three `-P` edges (empty entries, duplicate in mixed forms, order).

Research ran a prototype of exactly this against the unchanged hook, and the planner re-ran it:
every expected value below was observed. So these are regression gates that are green when first
written. Task 1 proves they can fail with a one-line mutation of a temp copy of the hook.

Purpose: the owner's Windows run (plans 09-04 to 09-06) is the second line of defence. Any later
Windows-branch fix (D-09, D-12) extends this block.
Output: the extended fake, nine new `windows_*` gates in `tests/test_discovery.sh` (the existing
`windows_` family of that file; no new prefix, no new test file, no new fake binary, per D-12).
</objective>
