re-pin.

How the statements meet the decisions (for the comment in tests/test_layout.py; facts from RESEARCH and the planner's pwsh 7.6.7 run):
- D-01: statements 2 to 4 are the lookup; an empty environment variable is skipped (`$r -and`), `-CommandType Application ... | Select-Object -First 1` takes one match; Git's `cmd\git.exe` sits next to `..\bin\sh.exe`.
- D-06/D-07 (research correction, intent kept): the not-found branch reads the payload only through the native `findstr`, because PowerShell's host reads all of stdin itself when the automatic input variable appears anywhere in the command text, even in a branch that never runs (ConsoleHost `IsUsingDollarInput`), and `sh.exe` would then inherit nothing. Planner refinement (revision 2; ROADMAP SC1: never a silent no-op; RESEARCH Open Question 1): `findstr /n /r "^"` prints every piped line it reads in full as `N:text` (it appends CR LF to a last line without LF), and the string is silent only when findstr exited 0, no output element fails the `^[0-9]+:` form (an error record, such as the too-long text, fails it) and no element matches `\.(bbj|src|bbx)` (`-match` is case-insensitive, D-06). A line findstr cannot read in full (its 8191-byte limit on piped input) is never printed, so a one-line payload then gives exit 1 and is reported, whether or not findstr prints its error; a `findstr` that cannot start leaves the exit code null and is reported. Codex writes the payload as one compact JSON line with no newline inside (rust-v0.162.1 `serde_json::to_string`), so the check does not depend on the payload's length. Accepted D-06 false positive: with no `sh.exe`, a non-BBj change whose payload line is too long for findstr is reported as well (the revision-1 string did the same whenever findstr printed its too-long text). Comparison operators only, so the branch stays ConstrainedLanguage-safe (D-05).
- D-02/D-05: stderr is written by the native `cmd /c echo ... 1>&2` (no method call, no decoration); Codex shows exit 2 with non-empty stderr as "Blocked by hook" (an exit 2 with empty stderr would be "Hook failed", Pitfall 3).
- D-08/D-09 (research correction, intent kept): the not-found branch sits before the call, so the string still ends with `exit $LASTEXITCODE`; statement 7 turns a launch that never set an exit code into exit 1 (Pitfall 4). `-Command` maps a native exit code other than 0 or 1 to 1 unless the string exits with it (09-WINDOWS-RUN.md).
- Codex (rust-v0.162.1) uses `command_windows` on Windows, replaces `${CLAUDE_PLUGIN_ROOT}` textually, prefers `pwsh` over `powershell` when found; the string is written in the 5.1 subset. The textual plugin root is kept (RESEARCH Open Question 6): it is the form proven on Windows in 09 round 2 and the one the pins expect.
- Message words avoid every self-scan term (RESEARCH Pitfall 10) and every character cmd treats specially except the deliberate `1>&2` and the `&` between echoes (Pitfall 6).
